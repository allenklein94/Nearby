## INVITE CONNECTION → INVITATION RECEIVED — WORKS, materially IMPROVED this pass
Two paths: (1) persisted `social_invites` row → Inbox's Invites tab (`getMyReceivedInvites()`) —
unchanged, still correct. (2) push notification tap → `routeNotificationTap()`. **This is the
one transition genuinely different since the last trace**: today's fix
(`services/notifications.js`, `RootNavigator.js`) closes a real, previously-undocumented bug
where a `gathering_invite` (or any) push tap that cold-starts the app from fully-closed was
silently dropped (`navigationRef.isReady()` was false, tap discarded, no retry). Now stashed to
AsyncStorage and replayed once the authenticated stack mounts. Verified present in current HEAD
(`consumePendingNotificationTap`/`PENDING_NOTIFICATION_TAP_KEY` both confirmed in the code).
**Not verified on-device** (cannot cold-start-launch via a real push in this sandbox) — logic
verified by direct code reading only, consistent with this repo's own standing limitation.

## CONNECTION → COMMUNITY — WORKS, this is the single biggest change since the last trace
The last trace (leg 5b) found this **MISSING** and deliberately left it unbuilt, flagged for a
future decision. It has since been built ("Start a Community from This Gathering," commit
`acbe36ed`) and was live-verified end-to-end against production at the time. Re-confirmed the
code is still present and internally consistent in the current repo:
- Entry point: `GatheringDetailScreen.js:477-490`, host-only, gated on
  `!gathering.community_id && new Date(gathering.scheduled_at) < new Date()` — correctly only
  offered post-event, for a gathering not already tied to a community.
- `seedCommunityFromGathering()` (`services/communities.js:14-39`) — fetches real approved
  `gathering_interest` rows, filters to real friends only (`filterToMyFriends`), invites each via
  the existing `sendInvite('community', ...)` (same friends+blocks-checked RPC every other
  community invite uses) — correctly does NOT attempt to auto-add non-friends (would fail
  `send_social_invite`'s own check anyway; pre-filtering avoids a silent partial failure).
- `CreateCommunityScreen.js` reads `route.params.seedFromGatheringId` and calls this right after
  a successful `createCommunity()` — confirmed still wired.
Not re-verified live this pass (already proven live end-to-end when built, code unchanged since,
no reason to suspect regression) — flagged as "verified previously, code-confirmed unchanged"
rather than "freshly live-verified this pass," per this refresh's own honesty standard.
