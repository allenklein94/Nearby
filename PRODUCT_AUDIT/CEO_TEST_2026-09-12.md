# Item 60 — The "CEO Test" (first-time-user obviousness audit)

User's framing, verbatim: open the app as someone who has never seen it before; don't explain
anything to yourself; ask, in order —

1. What is Nearby?
2. What can I do here?
3. How do I find something?
4. How do I meet/connect with someone?
5. How do I actually make something happen?

**Pass bar**: the answer to each question must be obvious from what's on screen, without chained
explanation ("well, you click here, then this opens another screen, then there's a hyperlink...").
If an answer requires that kind of multi-hop explanation, that's exactly the failure mode this
test exists to catch.

**Method note**: done as a full code trace of real screen copy/layout/navigation (no simulator/
device tooling available in this project, standing note). A code trace can't fully substitute for
an actual first tap-through, but it can catch real, concrete violations — missing/buried
copy, a CTA that doesn't say what it does, a path that needs 3+ hops to reach something a
first-time user would expect to find immediately.

Status: **DONE (2026-09-12)**. Full code trace of the real signed-out flow, `RootNavigator.js`'s
tab/stack structure, `HomeScreen.js`'s actual render order, `DiscoverHubScreen.js`'s mode/sub-mode
toggles, and the primary-CTA buttons on `GatheringDetailScreen.js`/`ViewProfileScreen.js`/
`BusinessProfileScreen.js`. `README.md` was skimmed for the app's own self-description and
contains none (`# Nearby` / `Nearby` — two lines, no tagline) — so the only real source of "what
is this app" framing is the onboarding screen itself, evaluated in Q1 below.

## Q1 — What is Nearby?

**Verdict: PASS.**

For someone who has never opened the app, `RootNavigator.js` puts `OnboardingScreen` first in the
signed-out stack (`Stack.Screen name="Onboarding"` is the first child under `!session`, so it's
React Navigation's default initial route — `src/navigation/RootNavigator.js:407`). That screen is
the literal first thing rendered, before any signup mechanics.

Its actual copy (`src/screens/OnboardingScreen.js:21-22`):

> **"Your next favorite memory could start today."**
> "Meet people, discover gatherings, and create experiences together."

This is plain language, no jargon, and names the three real pillars of the app (meet people /
discover gatherings / create experiences) in one sentence — a first-time user reads this in under
5 seconds, before tapping anything. The screen's own header comment
(`OnboardingScreen.js:7-12`) confirms this was a deliberate choice ("sells the outcome, not the
features... whatever someone needs to know about [notifications, privacy, discovery], they'll
learn by using the app").

Below the headline, two buttons are immediately visible and self-explanatory: **"Get Started"**
(→ `OnboardingQuestions`) and **"I already have an account"** (→ `Login`) —
`OnboardingScreen.js:26-42`. No ambiguity about what either does.

`README.md` itself has no tagline (`# Nearby` / `Nearby`), so this onboarding screen is the *only*
place the app explains itself — but it does the job on its own.

## Q2 — What can I do here?

**Verdict: PASS.**

The main app shell is 4 bottom tabs — Home / Discover / Create / Activity
(`RootNavigator.js:198-203`, `TAB_ICONS`) — plain, generic labels (no jargon like "Feed" or
"Nearby-verse"). By themselves the tab icons (house / compass / plus-circle / bell) don't explain
much, but `HomeScreen.js` (the landing tab) does the actual explaining, in this literal top-to-
bottom order for a first visit:

1. Greeting + subtitle ("What sounds good this morning?" — `HomeScreen.js:1239-1240`).
2. A visually-primary ask box: **"What do you want to do?"** with a text input and a **"Find it"**
   button (`HomeScreen.js:1245-1266`) — plus a small **"✨ Surprise Me"** link
   (`HomeScreen.js:1274-1283`).
3. **A real, one-time first-run card** (only shown until dismissed —
   `seen_home_first_run_moment` defaults `false` in the DB, confirmed in
   `supabase/migrations/20260829_home_first_run_moment.sql:9`, so a genuinely brand-new profile
   does see it): headed **"👋 This is Nearby"**, showing 1-2 real nearby items with real reasons
   attached, and closing with **"That's the idea — real things nearby, with a real reason
   attached. Ask for anything up top, or scroll down for more."** (`HomeScreen.js:1541-1576`).
   This is a genuine, concrete "here's what this app does" moment placed directly under the ask
   box — not buried.
4. Further down (if applicable): "Your Plans," "Nearby Right Now," category quick-picks,
   "Happening Near You," "Your Communities," then a "Quick Stats" card (people nearby / gatherings
   today / unread messages / friends — `HomeScreen.js:2051-2108`) and "Because You Like…".

Taken together (ask box + first-run explainer + real content sections), a first-time user reading
straight down Home — no taps required — gets a clear, concrete answer: you ask for things to do,
Nearby finds/suggests real nearby options, and you can also see your plans, browse communities,
and check stats. This clears the bar.

**One caveat, not a failure**: nothing on the tab bar or in Home's first-glance content (ask box,
first-run card) explicitly names "dating" or "meet people" as a feature — that value prop only
appeared once, in Q1's onboarding tagline, and doesn't resurface until the "Quick Stats" card's
generic "N people nearby" row, several sections down. A user who skipped past the onboarding
tagline quickly has no on-Home reminder that dating/friend-finding is even part of the app until
they scroll fairly far or open Discover. See fix list.

## Q3 — How do I find something?

**Verdict: PASS.**

The single most obvious element on Home, immediately visible with zero scrolling, is the ask box
described above: **"What do you want to do?"** with a placeholder that rotates through real
examples ("Dinner tonight…", "Something fun Saturday…", "Find a pickleball game…" —
`HomeScreen.js:47`) and a coral **"Find it"** button (`HomeScreen.js:1258-1266`). This is
self-evidently "type what you want, tap this button" — no explanation needed.

The **Discover** tab (compass icon, bottom tab bar) is the second, equally obvious answer for
browsing rather than typing: its header search bar reads **'Search, or try "something fun
Saturday"'** (`DiscoverHubScreen.js:1420`), sitting directly under the screen's own title
("Discover") and subtitle ("What are you looking for?" — `DiscoverHubScreen.js:147`), with type
filter chips (Gatherings/Communities/Places/Perks) directly below it.

Both surfaces are genuinely complementary, not confusingly redundant: Home's box is for a typed
"ask" that gets resolved into real matching supply across every content type at once; Discover's
search is for browsing/filtering a specific content type. A first-time user doesn't need to know
that distinction to succeed at "how do I find something" — either one obviously works, and both
are one tap or less from app open.

## Q4 — How do I meet/connect with someone?

**Verdict: PASS** (real, unambiguous path, exactly one tap inside the one tab a first-time user
would naturally try for "find/explore").

Chain, concretely: bottom tab bar → tap **"Discover"** (the natural tab for "how do I find X" in
general — compass icon, `RootNavigator.js:200`) → the very top of the screen, with zero scrolling,
shows a two-way toggle: **"🔎 Things to Do"** / **"👥 People"** (`DiscoverHubScreen.js:146-149`,
rendered at `DiscoverHubScreen.js:1375-1392`). Tapping **"People"** immediately reveals a second,
equally unambiguous toggle right below it: **"💗 Dating"** / **"🤝 Friends"**
(`DiscoverHubScreen.js:160-163`, rendered at `DiscoverHubScreen.js:1538-1556`) — both real,
separate, embedded matching surfaces (`DiscoveryScreen`/`FriendDiscoveryScreen`), swapped in place
with no further navigation.

This clears the bar: the labels are plain English ("People," "Dating," "Friends" — no jargon,
no ambiguous icons requiring interpretation), and the entire decision tree is visible the instant
Discover opens, with no scrolling and no second screen push.

**Also checked and correctly did *not* pass by accident**: Home's own "Quick Stats" card has an "N
people nearby" row (`HomeScreen.js:2063-2072`) that also reaches this same destination
(`navigation.navigate('Discover', { initialMode: 'people', initialPeopleSubMode: 'dating' })`) —
but it sits several sections down Home's scroll and is labeled only as a generic count, not as a
"meet people" action, so it doesn't materially help Q4 on its own; Discover's own toggle is what
actually earns the PASS here.

## Q5 — How do I actually make something happen?

**Verdict: PASS** across all three checked contexts. Every primary CTA is plain-language and
self-describing — a first-time user does not need the app's own vocabulary explained to know what
tapping it does.

**Gathering** (`GatheringDetailScreen.js:1093-1116`, the default not-yet-joined state — the one a
first-time visitor to any public gathering detail page actually sees): a single coral button whose
label is computed to literally say what it does — **"JOIN GATHERING"**, or **"REQUEST TO JOIN"**
for a non-public gathering, or **"JOIN WAITLIST"** if full
(`GatheringDetailScreen.js:1100-1105`) — with a secondary **"🤝 Invite a friend"** link underneath
(`GatheringDetailScreen.js:1107-1114`). No ambiguity.

**Person** (`ViewProfileScreen.js:427-469`): a stranger's profile shows **"🤝 Add Friend"**
(`:427-437`); once connected as both a friend and a dating match, the coral primary action becomes
**"🤝 Plan Together"** (routes straight to `DateProposal`, `ViewProfileScreen.js:450-459`) with
**"💬 Message"** as the secondary action (`:461-469`) — both plain verbs, no app-specific term
needing a friend to explain it.

**Business** (`BusinessProfileScreen.js:325-354`): the coral primary action is **"📅 Plan Here"**
(→ `MakeAPlan`, `:325-333`), with **"+ Follow"** and **"💬 Message"** as clearly secondary,
outlined actions below it (`:335-354`). "Plan Here" plainly reads as "make something happen at
this specific place."

All three of these were previously audited and made context-aware/coral under Item 37 (see
CLAUDE.md); this pass independently re-verified that the *labels themselves*, not just the color,
are self-explanatory to someone with zero prior context — they are.

## Prioritized fixes (small, buildable; nothing here requires a navigation/architecture change)

None of the 5 questions failed, so this list is short and consists of first-impression polish, not
bug fixes:

1. **(Highest value, cheapest)** Add one dating/friend-finding example to Home's rotating ask-box
   placeholder list (`HomeScreen.js:47`, `INTENT_PLACEHOLDER_EXAMPLES`) — e.g. "Meet new
   people…" — or work one into the first-run explainer card's copy
   (`HomeScreen.js:1547-1576`). Right now every placeholder/example a first-time user sees on
   Home is activity-shaped (dinner, Saturday plans, pickleball); nothing on first glance hints
   that People/Dating/Friends is also a whole mode of the app, which only resurfaces at Q4 via
   Discover. This is a one-line string change, not a new feature.
2. **(Cheap)** Consider moving the "Quick Stats" card's people-nearby row higher up Home's scroll
   order, or adding a one-line caption under it (e.g. "Tap to meet people nearby"), since today
   it's a bare number several sections down with no explicit "this is how you meet someone" framing
   (`HomeScreen.js:2051-2072`). Not required — Discover's own toggle already carries Q4 on its
   own — but it would reinforce the same idea earlier and higher on the one screen every user sees
   first after signing in.
3. **(Optional, cosmetic)** The tab bar's four labels (Home/Discover/Create/Activity) are generic
   by design and rely entirely on each tab's own screen content to convey capability — this is a
   defensible, common pattern (confirmed intentional per `RootNavigator.js:189-197`'s own comment
   on the 4-tab model) and not something to change without a larger navigation conversation; flagged
   here only so it's not mistaken for an oversight. No action recommended.

No item above requires restructuring navigation, adding a new tab, or any change bigger than a
copy/placeholder edit — all three are safely in "small polish" territory.
